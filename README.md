# Project Manager

Внутренний веб-инструмент для управления проектами: договоры, этапы, затраты,
бюджеты, табели сотрудников и финансы. Замена Excel/VBA-наработкам.

## Стек

- **Backend:** Go 1.22+, [chi](https://github.com/go-chi/chi) router
- **DB:** PostgreSQL 14+
- **Migrations:** [golang-migrate](https://github.com/golang-migrate/migrate) (встроены в бинарник через `embed`)
- **Auth:** bcrypt + cookie-сессии ([gorilla/sessions](https://github.com/gorilla/sessions))
- **Frontend:** HTML-шаблоны + собственный CSS + немного ванильного JS

## Требования

- Go 1.22 или новее
- PostgreSQL 14+
- Git

## Быстрый старт

### 1. Клонировать репозиторий

```
git clone https://github.com/oleoleg/project-manager.git
cd project-manager
```

### 2. Настроить окружение

```
cp .env.example .env
```

Минимальный набор переменных:

| Переменная | Назначение |
|---|---|
| `HTTP_PORT` | Порт HTTP-сервера (по умолчанию `8080`) |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Подключение к PostgreSQL |
| `SESSION_SECRET` | Секрет для cookie-сессий, **минимум 32 символа** |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_FULLNAME` | Первый админ, создаётся один раз, если таблица `users` пуста |

Пример генерации `SESSION_SECRET` (PowerShell):

```
-join ((1..48) | ForEach-Object { [char](Get-Random -Min 33 -Max 126) })
```

### 3. Запустить

```
go mod tidy
go run ./cmd/server
```

При первом запуске сервер:

1. Подключится к служебной БД `postgres` и создаст `DB_NAME`, если её нет.
2. Накатит миграции из `internal/db/migrations/`.
3. Создаст первого админа из `BOOTSTRAP_ADMIN_*`, если таблица `users` пуста.

Открыть: http://localhost:8080 → редирект на `/login`.

## Ключевые сущности

- **Контрагент** — справочник юридических лиц (ID — 4 цифры).
- **Договор** — реестр договоров. ID формата `NNNN-AA` (например `6666`, `6666-W`, `6666-W2`).
  Буквы (латиница): `W` — монтаж, `S` — поставка, `D` — проектирование.
  Назначается ответственный РП из числа пользователей.
- **Этап** — этапы внутри договора: №, наименование, стоимость, НДС %, аванс %,
  сроки, статус, вид работы.
- **Затраты этапа** — строки затрат по видам работ.

## Экономика этапа

### Понятия

- **Стоимость этапа** (`stage.cost`) — то, что мы продаём клиенту. Внешняя сумма.
- **Стоимость работ** — часть стоимости этапа, идущая на работу (ФОТп + маржа).
- **Затраты** — себестоимость.

### Формулы

**Разложение стоимости этапа на строки:**

```
Стоимость этапа = Стоимость работ
                + Командировочные
                + Оборудование (продажа)
                + Субподряд
                + Комиссия
                + Другое
```

**Затраты (себестоимость) — то, что показывается в «Затраты (план)»:**

```
Затраты = ФОТп
        + Командировочные
        + Оборудование (себестоимость)
        + Субподряд
        + Комиссия
        + Другое
```

**Убыток:**

```
Затраты > Стоимость этапа  →  этап убыточный (предупреждение, сохранить можно)
```

**Коэффициент** (не хранится в БД, вычисляется при отображении):

```
Коэф = ФОТп / Стоимость работ
```

### Автоматизация

- При вводе **т/з** или **ставки** → `ФОТп = ставка × т/з`.
- При ручном вводе **ФОТп** (без замка) → `т/з = ФОТп / ставка` (если ставка задана).
- **Замки** 🔒 на полях ФОТп / т/з / ставка фиксируют значения.
  Можно зафиксировать **до двух полей** — третье пересчитается.
- **Коэф** всегда вычисляется автоматически.

## НДС

Ставка НДС задаётся **у каждого этапа отдельно** (`stage.vat_percent`). Это позволяет
вести договоры со смешанными ставками (например, СМР — 22%, продажа ПО — 5%).

На странице договора есть переключатель **«Без НДС / С НДС»** — суммы пересчитываются
по ставке каждого этапа. **«Затраты» всегда без НДС** (это внутренняя себестоимость).

Если ставки у всех этапов договора одинаковые — под карточкой показывается
«без НДС (НДС 22%)» или «в т.ч. НДС 22%». Если разные — «смешанный НДС».
Если у этапа ставка 0 — «НДС не начисляется».

## Фильтры и переключатели

| Где | Переключатель | Что делает |
|---|---|---|
| Карточка договора | **Без НДС / С НДС** | Пересчёт сумм по ставке этапа |
| Карточка договора | **В работе / Все** | Показ незакрытых или всех этапов |
| Карточка договора | **Развернуть / Свернуть стоимости** | Показ колонок Стоимость / НДС / Аванс / Закрыто / Затраты |
| Форма этапа | **Компактный вид** | Скрытие колонок коэф / т/з / ставка |

## Приватность

В `/settings` можно включить опцию **«Скрывать финансовые показатели»** — все затраты
(«Затраты (план)», «Затраты (факт)») будут показаны в виде «пиксельной» плашки.
Оборот (стоимость, закрыто, остаток) остаётся видимым.

## Справочники в БД

- Статусы договора: `0` — заключение, `1` — в работе, `2` — закрытие, `3` — закрыт,
  `4` — закрыт с долгами, `5` — не пошло в реализацию.
- Статусы этапа: `0` — не активен, `1` — в работе, `2` — подписание актов,
  `3` — закрыт, `4` — закрыт с долгами, `5` — гарантия.
- Виды работ: ПИР, ППО, СМР, ПНР, Сборка, ТО, Ремонт, Продажа, Комплексный.
- Типы договоров: Подряд, Сервис, Поставка, Остальное.

## Интерфейс

- Светлая и тёмная темы (`/settings`).
- Автоформат денежных полей: `1 000 000.50` или `1000000,5`.
  Пробелы появляются динамически при вводе. Esc — откат, Enter — фиксация без submit.
- Сворачиваемые секции в карточке договора.
- Список этапов с кнопками ↑/↓ для изменения порядка, авто-нормализация `row_order`.
- Теги под наименованием этапа: вид работы, статус, ответственный.

## Схема БД (актуальная)

Справочники: `roles`, `contract_statuses`, `contract_types`, `procurement_card_statuses`,
`tracking_statuses`, `stage_statuses`, `work_kinds`.

Рабочие таблицы: `users`, `counterparties`, `contracts`, `contract_cards`,
`stages`, `stage_costs`, `stage_acts`.

Подробности — в `internal/db/migrations/`.

# Project Manager

Внутренний веб-инструмент для управления проектами: договоры, этапы, затраты, акты,
бюджеты, табели сотрудников и финансы. Замена Excel/VBA-наработкам.

📖 **[Полная документация — в Wiki](https://github.com/oleoleg/project-manager/wiki)**

## Стек

- **Backend:** Go 1.22+, [chi](https://github.com/go-chi/chi) router
- **DB:** PostgreSQL 14+
- **Migrations:** [golang-migrate](https://github.com/golang-migrate/migrate) (встроены в бинарник через `embed`)
- **Auth:** bcrypt + cookie-сессии ([gorilla/sessions](https://github.com/gorilla/sessions))
- **Frontend:** HTML-шаблоны + собственный CSS + ванильный JS (Chart.js для графиков)
- **Deployment:** Windows-служба ([kardianos/service](https://github.com/kardianos/service)) + трей ([energye/systray](https://github.com/energye/systray))
- **Installer:** Inno Setup

## Требования для разработки

- Go 1.22 или новее
- PostgreSQL 14+
- Git
- MinGW-w64 (gcc) — для сборки трея (CGO_ENABLED=1)

## Быстрый старт (для разработки)

### 1. Клонировать репозиторий

    git clone https://github.com/oleoleg/project-manager.git
    cd project-manager

### 2. Настроить окружение

    cp .env.example .env

Заполнить `.env`:

| Переменная | Назначение |
|---|---|
| `HTTP_PORT` | Порт HTTP-сервера для dev — `8081` |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Подключение к PostgreSQL. Для dev — `project_manager_dev` |
| `SESSION_SECRET` | Секрет для cookie-сессий, **минимум 32 символа** |
| `BOOTSTRAP_ADMIN_*` | Первый админ, создаётся один раз, если `users` пуста |

Пример генерации `SESSION_SECRET` (PowerShell):

    -join ((1..48) | ForEach-Object { [char](Get-Random -Min 33 -Max 126) })

### 3. Запустить

    go mod tidy
    go run ./cmd/app

Открыть: http://localhost:8081 → редирект на `/login`.

**Важно:** при `go run` приложение ищет `.env`, `web/` и `logs/`:
1. Рядом с `.exe` (для службы).
2. Иначе — в текущей рабочей директории (для dev).

## Развёртывание (Windows)

Приложение разделено на две части: **Сервер** (Служба + Трей) и **Клиент** (Агент).
Агент устанавливается на компьютеры пользователей (без прав администратора) и отвечает за открытие папок и файлов.

### Компоненты

- `project-manager.exe` — служба, крутит HTTP-сервер в фоне;
- `project-manager-tray.exe` — трей-процесс для админа (управляет службой);
- `pm-agent.exe` — клиентский агент для пользователей (перехватывает `pm-agent://`);
- `ProjectManager-Server-Setup.exe` — инсталлятор сервера;
- `ProjectManager-Agent-Setup.exe` — инсталлятор клиента.

### Сборка

1. Заполни `.env.production` (или `.env.production.example`).
2. Запусти **`build.bat` от имени администратора** (собирает бинарники в `dist/`).
3. Запусти **`package.bat`** (собирает инсталляторы через Inno Setup).

### Локальная установка службы

Запусти **`install.bat` от имени администратора** — установит службу, запустит трей, выдаст права пользователям.
Удаление — **`uninstall.bat` от имени администратора**.

### Установка через инсталлятор

**Сервер (ProjectManager-Server-Setup.exe):**
1. Запусти от имени администратора.
2. Заполни три страницы визарда: PostgreSQL, HTTP-порт, Логин/пароль администратора.
3. Инсталлятор создаст `.env`, зарегистрирует службу и протокол `pm-agent://`, установит Трей и Агент.

**Клиент (ProjectManager-Agent-Setup.exe):**
1. Запусти (права администратора **не нужны**).
2. Укажи IP-адрес и порт сервера.
3. Инсталлятор установит `pm-agent.exe` в `%LOCALAPPDATA%\Project Manager Agent` и зарегистрирует протокол `pm-agent://` для текущего пользователя.

### Управление (Сервер)

- **Служба:** `services.msc` → `Project Manager`.
- **Трей:** правый клик на иконке:
  - **Открыть в браузере** — `http://localhost:8080`;
  - **Запустить / Остановить / Перезапустить службу**;
  - **Открыть лог** — `logs/project-manager.log` в Блокноте;
  - **⚙ Настройки** — открывает `tray.config.json`;

|---|---|---|
| Администратор | `admin` | Управление пользователями, полный доступ |
| Начальник РП | `rp_chief` | Полный доступ, назначение ответственных |

| Бухгалтер | `accountant` | Доступ на чтение ко всему |

## Ключевые сущности

- **Контрагент** — справочник юридических лиц (ID — 4 цифры).
- **Договор** — реестр договоров. ID формата `NNNN-AA`.
- **Этап** — этапы внутри договора: №, наименование, стоимость, НДС %, аванс %, сроки, статус.
- **Затраты этапа** — строки затрат по видам работ (ФОТп, командировочные, оборудование, субподряд, комиссия, другое).
- **Акт** — денежный документ. Может закрывать один или несколько этапов.
- **Приложение** — информационный акт (УПД, счёт-фактура, КС-2 и т. п.), привязанный к главному акту.
- **Бюджет (ФинПлан)** — сгенерированный снимок финансового плана на основе этапов и затрат. Имеет версионность и статус утверждения.

## Экономика этапа

- **Стоимость этапа** — продажа клиенту.
- **Затраты** = `ФОТп + Командировочные + Обор. (себест.) + Субподряд + Комиссия + Другое`.
- **Убыток** — если `Σ затрат > Стоимость этапа`.
- **Коэф** = `ФОТп / Стоимость работ` — только для отображения, в БД не хранится.
- **Замки** 🔒 на ФОТп / т/з / ставке — фиксируют значения (до двух одновременно).

## НДС

Ставка НДС задаётся **у каждого этапа отдельно**. Переключатель **«Без НДС / С НДС»** на странице договора пересчитывает суммы по ставке каждого этапа.

## Работа с актами

- **📎** — есть привязанные акты.
- **🔗** — сумма «Закрыто» совпадает с суммой актов.
- **🔒** — «Закрыто» введено вручную.

## Открытие файлов проекта

Файлы на сервере открываются через URL-протокол **`pm-agent://`**. При клике браузер вызывает `pm-agent.exe`, который открывает папку или файл в проводнике (или в нативной программе, например, Word/PDF). Это позволяет обойти ограничения безопасности браузеров и открывать сетевые пути (в том числе `\\Work\...`).

## Бюджет договора (ФинПлан)

- **Создание:** В карточке договора есть кнопка «Бюджет». Нажатие «Создать новый план» открывает настройки (даты, отсрочки, коэффициенты), после чего генерируется снимок.
- **Версионность:** Каждый сгенерированный план сохраняется как снимок. Его нельзя изменить, но можно переключиться на старую версию или удалить.
- **Утверждение:** Снимок можно зафиксировать кнопкой «Утвердить руководством». В истории сохранится дата и ФИО утвердившего.
- **Детализация:** Таблица плана с автоматической группировкой по типам операций, датам или видам работ с промежуточными итогами.
- **Сводка:** Круговые диаграммы распределения затрат и прибыли (Chart.js).
- **Правила генерации:** Аванс, Оплата по договору, Зарплата (ФОТп), Накладные, Оборудование, Субподряд, Командировки и прочее — рассчитываются автоматически на основе таблиц этапов и затрат.

# Project Manager

Внутренний веб-инструмент для управления проектами: договоры, этапы, затраты,
бюджеты, табели сотрудников и финансы. Замена Excel/VBA-наработкам.

## Стек

- **Backend:** Go 1.22+, [chi](https://github.com/go-chi/chi) router
- **DB:** PostgreSQL 14+
- **Migrations:** [golang-migrate](https://github.com/golang-migrate/migrate) (встроены в бинарник через `embed`)
- **Auth:** bcrypt + cookie-сессии ([gorilla/sessions](https://github.com/gorilla/sessions))
- **Frontend:** HTML-шаблоны + собственный CSS + немного ванильного JS
- **Deployment:** Windows-служба ([kardianos/service](https://github.com/kardianos/service)) + трей ([energye/systray](https://github.com/energye/systray))
- **Installer:** Inno Setup

## Требования для разработки

- Go 1.22 или новее
- PostgreSQL 14+
- Git
- MinGW-w64 (gcc) — для сборки трея (`CGO_ENABLED=1`)

## Быстрый старт (для разработки)

### 1. Клонировать репозиторий

```
git clone https://github.com/oleoleg/project-manager.git
cd project-manager
```

### 2. Настроить окружение

```
cp .env.example .env
```

Заполнить `.env` для локальной разработки:

| Переменная | Назначение |
|---|---|
| `HTTP_PORT` | Порт HTTP-сервера для dev — `8081` (чтобы не конфликтовать со службой на `8080`) |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Подключение к PostgreSQL. Для dev используй `project_manager_dev` |
| `SESSION_SECRET` | Секрет для cookie-сессий, **минимум 32 символа** |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_FULLNAME` | Первый админ, создаётся один раз, если таблица `users` пуста |

Пример генерации `SESSION_SECRET` (PowerShell):

```
-join ((1..48) | ForEach-Object { [char](Get-Random -Min 33 -Max 126) })
```

### 3. Запустить в режиме разработки

```
go run ./cmd/app
```

Открыть: http://localhost:8081 → редирект на `/login`.

**Важно:** при запуске из `go run` приложение ищет `.env`, `web/` и `logs/`:
1. Рядом с exe (для службы).
2. Иначе — в текущей рабочей директории (для dev-режима).

## Развёртывание (Windows)

Приложение разворачивается как **служба Windows** с **иконкой в трее**.

### Компоненты

- `project-manager.exe` — служба, крутит HTTP-сервер в фоне;
- `project-manager-tray.exe` — трей-процесс, даёт управление службой;
- `ProjectManager-Setup.exe` — инсталлятор (собирается через Inno Setup).

### Сборка

1. Убедись, что `.env.production` (или `.env.production.example`) заполнен.
2. Запусти **`build.bat` от имени администратора**. Он соберёт:
   - `dist/project-manager.exe`
   - `dist/project-manager-tray.exe`
   - `dist/project-manager-debug.exe` (с консолью — для отладки)
   - `dist/.env` (копия `.env.production`)
   - `dist/web/` (шаблоны и статика)

**Почему от администратора:** `build.bat` останавливает службу перед очисткой `dist` (иначе файлы заняты).

### Локальная установка службы

Запусти **`install.bat` от имени администратора**:

- остановит и удалит старую службу, если была;
- установит новую;
- запустит трей;
- выдаст пользователям права на управление службой (`sc sdset`).

Удаление — **`uninstall.bat` от имени администратора**.

### Сборка инсталлятора

1. Установи [Inno Setup 6+](https://jrsoftware.org/isdl.php).
2. Собери `dist/` через `build.bat`.
3. Запусти **`package.bat` от имени администратора**.

Результат: `dist\ProjectManager-Setup.exe`.

### Установка через инсталлятор

1. Скопируй `ProjectManager-Setup.exe` на целевую машину.
2. Запусти от имени администратора.
3. В визарде укажи:
   - адрес, порт, пользователя, пароль БД;
   - имя базы данных;
   - HTTP-порт;
   - логин и пароль администратора приложения.
4. Инсталлятор создаст `.env`, распакует файлы, зарегистрирует службу, запустит трей.

### Управление

- **Служба:** `services.msc` → `Project Manager`, или `sc.exe start|stop ProjectManager`.
- **Трей:** правый клик на иконке:
  - **Открыть в браузере** — `http://localhost:8080`;
  - **Запустить / Остановить / Перезапустить службу** — неактивные пункты серые;
  - **Открыть лог** — `logs/project-manager.log` в Блокноте;
  - **Папка логов**;
  - **⚙ Настройки** — открывает `tray.config.json`;
  - **↻ Применить настройки** — перечитать конфиг;
  - **Выход (только трей)** — служба продолжает работать.

### Настройки трея (`tray.config.json`)

Файл создаётся автоматически при первом запуске трея рядом с `.exe`:

```json
{
  "monitor_enabled": true,
  "monitor_interval_sec": 5,
  "autostart": false
}
```

- `monitor_enabled` — периодически опрашивать состояние службы (для серых кнопок). `false` — отключить опрос полностью.
- `monitor_interval_sec` — интервал опроса в секундах (минимум 2).
- `autostart` — добавлять трей в автозагрузку текущего пользователя.

После правки — в меню трея **↻ Применить настройки**.

### Логи

Пишутся в файл `logs/project-manager.log` рядом с `.exe` службы.
Пишутся строки старта, останова, миграций, ошибок.

### Удаление

- **Из «Установка и удаление программ»** — деинсталлятор остановит и удалит службу, уберёт файлы.
- **Из консоли:** `uninstall.bat` от имени администратора.

## Роли и права

| Роль | Код | Права |
|---|---|---|
| Администратор | `admin` | Управление пользователями, полный доступ |
| Начальник РП | `rp_chief` | Полный доступ, назначение ответственных |
| Директор | `director` | Просмотр всего, редактирование договоров, статистика |
| Руководитель проектов | `rp` | Редактирует **только свои** договоры (где назначен ответственным) |
| Бухгалтер | `accountant` | Доступ на чтение ко всему |

## Ключевые сущности

- **Контрагент** — справочник юридических лиц (ID — 4 цифры).
- **Договор** — реестр договоров. ID формата `NNNN-AA` (например `6666`, `6666-W`, `6666-W2`).
  Буквы (латиница): `W` — монтаж, `S` — поставка, `D` — проектирование.
  Имеет поле **«Путь к корню проекта»** — UNC или локальный путь к папке на сервере.
  По кнопке «📁 Открыть папку» через URL-протокол `pm://` открывается в проводнике.
- **Этап** — этапы внутри договора: №, наименование, стоимость, НДС %, аванс %, сроки, статус, вид работы.
- **Затраты этапа** — строки затрат по видам работ.

## Экономика этапа

- **Стоимость этапа** — то, что продаём клиенту.
- **Затраты** = `ФОТп + Командировочные + Обор. (себест.) + Субподряд + Комиссия + Другое`.
- **Убыток** — если `Σ затрат > Стоимость этапа`.
- **Коэф** = `ФОТп / Стоимость работ` — только для отображения, в БД не хранится.
- **Замки** 🔒 на ФОТп / т/з / ставке — фиксируют значения (до двух одновременно).

## НДС

Ставка НДС задаётся **у каждого этапа отдельно** (`stage.vat_percent`).
Переключатель **«Без НДС / С НДС»** на странице договора пересчитывает суммы по ставке каждого этапа.
«Затраты» всегда без НДС.

## Если что-то ломается

### `internal error` в браузере после входа

Скорее всего, сменился `SESSION_SECRET`, а браузер хранит старую cookie.
**Решение:** очистить cookie для `localhost` в браузере (DevTools → Application → Cookies) или зайти в инкогнито.

### Служба падает с ошибкой 1067

Смотри `logs/project-manager.log`. Обычные причины: нет `.env`, нет папки `web/` рядом с `.exe`, БД недоступна.

### `pattern matches no files` при старте

`baseDir` определён неверно. Проверь, что рядом с `exe` есть `web/templates`, а `.env` в той же папке.

### Двойной запуск на одном порту

Закрой предыдущий процесс: `Ctrl+C` в терминале с `go run`, или:

```powershell
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8081 -State Listen).OwningProcess -Force
```

# Project Manager

Внутренний веб-инструмент для управления проектами: договоры, этапы, бюджеты,
табели сотрудников и финансы. Замена Excel/VBA-наработкам.

## Стек

- **Backend:** Go 1.22+, [chi](https://github.com/go-chi/chi) router
- **DB:** PostgreSQL 14+
- **Migrations:** [golang-migrate](https://github.com/golang-migrate/migrate) (встроены в бинарник через `embed`)
- **Auth:** bcrypt + cookie-сессии ([gorilla/sessions](https://github.com/gorilla/sessions))
- **Frontend:** HTML-шаблоны + собственный CSS + немного ванильного JS

## Требования

- Go 1.22 или новее
- PostgreSQL 14+
- Git

## Быстрый старт

### 1. Клонировать репозиторий

```
git clone https://github.com/oleoleg/project-manager.git
cd project-manager
```

### 2. Настроить окружение

```
cp .env.example .env
```

Минимальный набор переменных:

| Переменная | Назначение |
|---|---|
| `HTTP_PORT` | Порт HTTP-сервера (по умолчанию `8080`) |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Подключение к PostgreSQL |
| `SESSION_SECRET` | Секрет для cookie-сессий, **минимум 32 символа** |
| `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_ADMIN_FULLNAME` | Первый админ, создаётся один раз, если таблица `users` пуста |

Пример генерации `SESSION_SECRET` (PowerShell):

```
-join ((1..48) | ForEach-Object { [char](Get-Random -Min 33 -Max 126) })
```

### 3. Запустить

```
go mod tidy
go run ./cmd/server
```

При первом запуске сервер:

1. Подключится к служебной БД `postgres` и создаст `DB_NAME`, если её нет.
2. Накатит миграции из `internal/db/migrations/`.
3. Создаст первого админа из `BOOTSTRAP_ADMIN_*`, если таблица `users` пуста.

Открыть: http://localhost:8080 → редирект на `/login`.

## Роли и права

| Роль | Код | Права |
|---|---|---|
| Администратор | `admin` | Управление пользователями, полный доступ ко всему |
| Начальник РП | `rp_chief` | Полный доступ, назначение ответственных |
| Директор | `director` | Просмотр всего, редактирование договоров, статистика |
| Руководитель проектов | `rp` | Редактирует **только свои** договоры (где назначен ответственным) |
| Бухгалтер | `accountant` | Доступ на чтение ко всему |

## Ключевые сущности

- **Контрагент** — справочник юридических лиц (ID — 4 цифры).
- **Договор** — реестр договоров. ID формата `NNNN-AA` (например `6666`, `6666-W`, `6666-W2`).
  Буквы (латиница): `W` — монтаж, `S` — поставка, `D` — проектирование.
  Назначается ответственный РП из числа пользователей.
- **Карточка договора** — надстройка над договором (процент накладных расходов).
- **Этап** — этапы внутри договора: № , наименование, стоимость, НДС, аванс, сроки, статус, вид работы.
- **Затраты этапа** *(в разработке)* — ФОТп, коэффициент, трудозатраты, субподряд, оборудование.
- **Акт** *(в разработке)* — акты по этапам.

## Справочники в БД

- Статусы договора: `0` — заключение, `1` — в работе, `2` — закрытие, `3` — закрыт,
  `4` — закрыт с долгами, `5` — не пошло в реализацию.
- Статусы этапа: `0` — не активен, `1` — в работе, `2` — подписание актов,
  `3` — закрыт, `4` — закрыт с долгами, `5` — гарантия.
- Виды работ: ПИР, ППО, СМР, ПНР, Сборка, ТО, Ремонт, Продажа, Комплексный.
- Типы договоров: Подряд, Сервис, Поставка, Остальное.

## Интерфейс

- Светлая и тёмная темы, переключаются в **Настройках** (`/settings`).
- Автоформат денежных полей (пробелы между разрядами), можно вводить `1 000 000.50` или `1000000,5`.
- Сворачиваемые секции в карточке договора.
- Список этапов с кнопками ↑/↓ для изменения порядка.

## Схема БД (актуальная)

Справочники: `roles`, `contract_statuses`, `contract_types`, `procurement_card_statuses`,
`tracking_statuses`, `stage_statuses`, `work_kinds`.

Рабочие таблицы: `users`, `counterparties`, `contracts`, `contract_cards`,
`stages`, `stage_costs`, `stage_acts`, `contract_assignees`.

Подробности — в `internal/db/migrations/`.
